# 统一商户后台迁移清单

原版及classic只读保留。迁移目标为18827同一个React应用、同一个外壳和内部hash路由，禁止使用iframe或跳往旧端口完成业务。

| 原有页面 | 必须保留的功能 | 新应用路由 |
|---|---|---|
| 工作台 | 今日待核销、待称重、饮品、快捷操作；老板账目摘要；员工只看岗位 | /dashboard |
| 订单 | 状态/渠道/搜索筛选、详情、关联入园与称重收款记录、演示退款 | /orders |
| 验券 | 券码查询、有效/过期/已核销/已退款、确认核销、原因必填撤销、已完成禁止撤销 | /verify |
| 称重 | 关联同一订单，毛重/皮重kg、净重kg/斤、元/斤、整数克/分、负值与精度拒绝、幂等收款 | /weigh |
| 饮品 | 待制作→制作中→待取餐→已取餐、取餐号与备注、防止重复推进 | /drinks |
| 商品 | 搜索/分组/状态筛选、上下架、售罄、上架库存、批量下架/售罄 | /products |
| 预约 | 场次、人数/组数/团数、已约容量、暂停/开放、不能低于已约 | /reservations |
| 账目 | 分渠道明细、订单金额/退款/实收/手续费/待结算/已到账分开；不计算利润 | /ledger |
| 推荐奖励 | 待结算/已结算/退款调整、完成订单后示例结算、不转账、规则未确认 | /rewards |
| 设置 | 平台待授权、岗位范围、审计记录、重置演示 | /settings |
| 当前流量页 | 保留所有已有总览/趋势/来源/排行交互 | /traffic |

## 状态策略
- 复用原业务模型的完整源码，保留整数克/分算法和权限、退款、奖励、审计逻辑；原文件不改。
- React应用使用独立演示存档；同源存在旧存档时可首次复制，不回写旧版。
- 入园券订单ID就是到访关联ID，核销、称重、收款、账目、奖励都引用同一ID。
- 浏览器刷新与菜单/返回不清空业务状态。视图权限为演示，不是服务端鉴权。
- 所有支付、核销、退款及奖励结算均为本机模拟，不接平台、不收集个人资料。
